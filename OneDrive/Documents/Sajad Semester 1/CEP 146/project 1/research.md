\### Project Research: Open Source Movement and Licensing Changes



\### 1. Key Definitions



\* \*\*Open Source Initiative (OSI):\*\* The governing body that validates true open-source compliance based on the Open Source Definition (OSD).

\* \*\*Permissive Licenses (MIT / Apache 2.0):\*\* Allows full commercial use, modification, and closing of code source.

\* \*\*Copyleft Licenses (GPL / AGPL):\*\* Requires any downstream modifications to also remain completely open-source.



\### 2. The Cloud Poaching Problem



\* Cloud providers (primarily Amazon Web Services) took free open-source software, packaged it as profitable managed services, and gave back minimal revenue or code up-stream.



\### 3. Core Case Studies (The Shift to Source-Available)



\* \*\*MongoDB (2018):\*\* Shifted to Server Side Public License (SSPL). Requires anyone selling it as a service to open-source their entire infrastructure stack.

\* \*\*HashiCorp (2023):\*\* Shifted Terraform from Apache 2.0 to Business Source License (BSL 1.1) to block commercial hosting competitors.

\* \*\*Redis (2024):\*\* Moved from BSD to a dual SSPL/RSALv2 model, blocking cloud giants from free hosting exploitation.



\### 4. Community Counter-Forks



\* \*\*OpenTofu:\*\* A community-led fork of Terraform managed under the Linux Foundation.

\* \*\*Valkey:\*\* A community fork of Redis backed by AWS, Google, and Oracle under the Linux Foundation.
